# Рабочее место ДИТ OPS · УОР

## Запуск

На Windows, macOS и Linux нужен Node.js 20.19 или новее. В корне распакованного проекта выполните одну команду.

```text
npm run dev
```

Откройте [рабочее место](http://127.0.0.1:4179/). `npm start` запускает то же приложение. Если доступен только Node.js, выполните `node src/server.mjs`. Установка npm-пакетов для карты и статусов не требуется. При первом запуске карта и Excel копируются из `seed` в `.local`. PDF и PPTX находятся в `reference`. Для обмена общими результатами нужен Git, для браузерных подключений нужен Playwright и совместимый Chromium-браузер.

## Первый рабочий сценарий

1. Для просмотра откройте «Итоги». Выберите цель, участника и период. Опубликованные и локальные значения подписаны отдельно.
2. В «Настройка → Источники» загрузите карту целей HTML и нужную книгу XLSX. Карта и справочник заполнятся из HTML. Вкладки Excel можно открыть, а оригиналы скачать.
3. В «Настройка → Цели и статусы» выберите цель и нажмите «Добавить статус» или «Изменить статус». Укажите период, дату факта и значение. План, комментарий и риски находятся под полями статуса.
4. Для общей публикации укажите HTTPS-адрес репозитория в «Настройка → Профиль и Git» и нажмите «Проверить обновления». В «Цели и статусы» нажмите «Отправить данные» и отметьте нужные цели. Права на запись определяет репозиторий. На каждом рабочем месте загрузите одну и ту же карту для названий и привязок участников.
5. В «Настройка → Автоматизация» выберите цель, лист XLSX, колонки и границы данных. Если в ячейке хранится 0,8 для 80%, выберите формат «Доля». Проверьте значения и примите расчёт локально. Справочник редактируется в «Настройка → Справочники», копия с оригиналами скачивается из «Профиль и Git».

В «Настройка → Статусы ДИТ» выберите статусы и нажмите «Отправить в Git». Правки сохранятся локально перед предпросмотром. Сброс ручного статуса возвращает цель к отдельному итогу ДИТ из Excel, если такой итог есть. После публикации коллеги получат ручные статусы при обновлении из той же ветки.

Там же через «Указать факт» внесите проверенное число с датой и основанием, выберите итоговую ячейку XLSX или рассчитайте долю по двум ячейкам. До публикации правка видна на вашей установке. «Итоги → Срезы ДИТ» показывает источник и позволяет выгрузить JSON.

На карте видны дата Excel и полнота данных ДИТ через счётчики целей с фактом и статусом. Для цели, которая не оценивается в выбранном периоде, используйте «Настройка → Статусы ДИТ». Даты наблюдений сравниваются в «Итоги → Срезы ДИТ». При риске можно создать локальное поручение. «Настройка → Год качества» рассчитывает технический пилот по явно выбранным колонкам и сохраняет отчёт с отклонениями.

Резервное копирование и восстановление находятся в «Настройка → Профиль и Git». Подтверждайте замену после сверки состава копии. [Что входит в копию и как её восстановить](docs/sdd/restore.md)

В «Итоги → Еженедельный отчёт → К встрече» выберите весь ДИТ и все кластеры или одного ИТ-лидера. Настройте разделы, проверьте слайды и нажмите «Скачать PPTX». Шаблон сохраняется на этой установке. [Состав презентации и источники](docs/sdd/meeting-deck.md)

Для детализации зрелости включите раздел «Модель зрелости SW26.1» и выберите отдельный XLSX. В отчёте одного лидера проверьте соответствия кластеров. [Правила детализации](docs/sdd/meeting-deck.md#модель-зрелости-sw261)

В «Профиль и Git» можно указать полный путь к `git.exe` из [Portable Git](https://git-scm.com/install/windows) и проверить его кнопкой «Проверить Git». Режим «Спрашивать логин и пароль» запрашивает их при отправке и ручном обновлении. В поле пароля можно ввести токен, если репозиторий поддерживает его для HTTPS Git. Данные входа используются на время операции. В этом режиме проверка общих обновлений запускается вручную.

«Итоги → Статусы целей» показывает цели ДИТ или назначения ИТ-лидеров. Выберите период, статус и лидера. План и факт берутся из применимых строк Excel. Карточка цели показывает связанные строки с листом и номером строки. Клик по «Под риском» на карте сразу открывает нужный разрез реестра.

В «Настройка → Сверка КР» выберите книгу, сохраните подтверждённую дату среза и сопоставьте строки с целями. Связь для того же КР и периода используется при загрузке следующей книги. С одним датированным срезом «Итоги → Еженедельный отчёт» показывает текущие риски и КР без методики. Для сравнения выберите две книги с разными датами и общим периодом.

Оформление меняется в «Настройка → Профиль и Git». «Системная» следует настройкам компьютера. Выбранная палитра сохраняется на этой установке.

Графики собираются в «Настройка → Конструктор графиков» и открываются в «Итоги → Визуализация». Карточки показывают назначения за выбранный период. При общем охвате график показывает кластеры отдельно. Нажатие на группу открывает соответствующий список целей. Сводка ДИТ показывает уникальные цели и их статусы.

«Настройка → Браузерные подключения» поддерживает получение XLSX и чтение текста выбранного блока страницы. См. [настройку СберБраузера и Playwright](docs/browser-connectors.md).

Пример для приложенной книги от 3 ноября. Для «Базовых практик модели зрелости» используйте основной лист, участника в столбце P, факт Q4 в G, строку перед данными 135 и последнюю строку 143. Укажите дату среза после сверки. Это перенос заявленных процентов из сводки. Формула зрелости по сырым метрикам проверяется на отдельной выгрузке.

Для подключения конкретных отчётов ОКО, СберТрека или Навигатора проверьте адреса, вход и выгрузку на рабочем компьютере.
