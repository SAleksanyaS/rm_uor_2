# Действия по рискам и подключение СберТрека

## Локальная задача

Из карточки риска можно создать задачу, назначить ответственного, поставить срок и записать следующее действие. Состояние задачи обновляется вручную: «Открыта», «В работе», «Выполнена». Смена состояния задачи сама по себе не меняет статус цели. Задача хранится в рабочем состоянии и попадает в локальную резервную копию. Рабочее место использует её независимо от доступности СберТрека.

| Что хранится | Правило |
| --- | --- |
| `goalId`, `scopeId`, `period` | Цель, уровень ДИТ или конкретный участник, отчётный период |
| `snapshotId`, `week` | Ссылка на исходный срез и опциональная дата начала недели, если эти данные есть в точке создания. Отсутствующие значения хранятся как `null` |
| `title`, `owner`, `dueOn`, `nextAction` | Название, ответственный, срок и следующее действие. Срок хранится как календарная дата `YYYY-MM-DD` |
| `status` | `open`, `in-progress`, `done` |
| `id`, `revision` | Стабильный идентификатор задачи и меняющаяся ревизия |
| `createdAt`, `createdBy`, `updatedAt`, `updatedBy` | Время и автор создания и последней правки |

Привязка сохраняется при редактировании. Для обновления нужна текущая ревизия. При конфликте рабочее место показывает, что задачу надо открыть заново, и сохраняет последнюю принятую версию. Задачи доступны в разрезе того же риска и в локальном списке. Подпись автора берётся из профиля рабочего места.

## Контракт для подключения

Создание задачи в СберТреке — отдельная операция после явного действия пользователя. Локальный модуль `riskTaskRequest(action)` готовит данные для будущего адаптера: `operationId`, название, ответственный, срок, следующее действие и привязка к риску. `operationId` совпадает с локальным ID задачи. Секреты и параметры корпоративного подключения в этот объект не входят. Действующее приложение сохраняет задачу локально. Доступ и отправка в СберТрек требуют подтверждённого корпоративного контракта.

| Что уточнить у владельца интеграции | Что зависит от ответа |
| --- | --- |
| Поддерживаемая версия API и точный адрес операции создания | Единственный разрешённый HTTPS-адрес для запроса `POST` |
| Тестовый проект, тип задачи, обязательные поля и способ адресовать проект | Проверка настроек и преобразование запроса |
| Способ входа, разрешения и требования к сертификатам | Кто авторизует создание и каким штатным способом приложение получает доступ |
| Справочник пользователей и допустимый ключ исполнителя | Явное сопоставление локального имени с корпоративным идентификатором. Неоднозначность останавливает отправку |
| Форматы срока, описания и привязки | Преобразование полей без предположений о допустимых именах и типах |
| Поля ответа, авторство и подтверждение результата | Получение ключа и ссылки из подтверждённого ответа СберТрека |
| Идемпотентность, повторная сверка и ограничения API | Как найти задачу по операции, подтвердить уже выполненный запрос и избежать дубля |
| Состав данных, который разрешено переносить | Какие сведения о риске и источнике можно включить в описание |

После согласования отдельный адаптер предоставляет операцию `create(request, { signal })`. Он получает разрешённую конфигурацию и авторизацию на серверной стороне, проверяет назначение и преобразует подготовленный запрос в фактический API. Перед отправкой приложение показывает проект, тип и выбранные поля. Ответ считается успешным после получения и проверки ключа задачи и ссылки на согласованный адрес. В рабочем состоянии сохраняются ключ, ссылка и время подтверждения. Локальное состояние задачи и состояние отправки хранятся отдельно.

### Где менять проект

| Место | Что добавить |
| --- | --- |
| `src/risk-actions.mjs` | Использовать готовый `riskTaskRequest(action)`. Сохранить стабильный ID для повторов и единый контракт локальных задач |
| Новый `src/sbertrack-task-provider.mjs` | Реализовать `create` для согласованного адреса, способа входа и обязательных полей. Здесь же проверять ответ и выполнять сверку после неизвестного результата |
| `src/workspace.mjs` | Связать ревизию задачи и отдельный статус отправки, сохранить ключ и ссылку после подтверждённого ответа. Надёжно обработать повтор и параллельную правку |
| `src/server.mjs` и [HTTP](http.md) | Добавить отдельную операцию предпросмотра и подтверждённой отправки. Контракт и обработчики очереди остаются на локальном сервере |
| `public/risk-actions-view.js` и `public/app.js` | Показать выбранный проект и поля, кнопку отправки, результат со ссылкой и повторную сверку. Настройка подключения относится к «Настройке», исходная локальная задача открывается из рисков |

Повтор использует тот же ID операции и поддержанный механизм идемпотентности либо подтверждённое чтение по корреляции, если их предоставляет API. После тайм-аута с неизвестным результатом приложение сначала сверяет наличие задачи. Если API не поддерживает такую сверку, повтор требует явной проверки пользователем. При отказе доступа, некорректных полях или недоступности сервиса локальная задача остаётся доступной.

## Проверки

| Сценарий | Ожидаемый результат |
| --- | --- |
| Риск кластера, создание и обновление | Цель, кластер, период и источник сохраняются. Смена состояния задачи сохраняет статус риска |
| Две формы одной задачи | Первая правка проходит. Вторая получает конфликт и не заменяет принятую версию |
| Перезапуск без подключения | Задача, ответственный, срок и следующее действие доступны из локального состояния |
| Приёмка адаптера в целевой среде | Явное создание в тестовом проекте даёт подтверждённый ключ и ссылку. Отказ доступа сохраняет задачу. Потеря ответа и повтор не дают дубля |
