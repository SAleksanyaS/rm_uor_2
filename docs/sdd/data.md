# Данные, идентификаторы и расчёты

[SDD](../SDD.md) · [HTTP](http.md) · [Экраны](screens.md)

## Файлы данных

| Место | Содержимое и жизненный цикл |
| --- | --- |
| `seed/workspace.json`, `seed/sources/` | Начальный каталог, профиль и оригиналы. В штатном CLI копируются в пустое рабочее пространство по умолчанию. Повторный запуск сохраняет рабочие изменения |
| `reference/` | PDF и PPTX для справки. Приложение их не читает |
| `<dataDir>/workspace.json` | Рабочее состояние `schemaVersion: 1`. Один пишущий сервер на каталог. Записи проходят очередь, затем временный файл заменяет основной |
| `<dataDir>/sources/<sha256>` | Оригинальные байты HTML/XLSX. Идентификатор вычисляется из содержимого, одинаковые байты переиспользуются |
| `<dataDir>/git/` | Служебное Git-хранилище общей версии и временная подготовка выпуска |
| `<dataDir>/browser/workspace.json` | Настройки, задания, последние тексты, архив недель и записи действий. Формат `schemaVersion: 1`, отдельная очередь записи |
| `<dataDir>/browser/profiles/`, `locks/`, `downloads/` внутри `browser/` | Личные сессии Chromium, блокировки профилей и временные файлы скачивания |
| `data/rm-uor.json` в настроенной Git-ветке | Общая версия результатов и история. Объём JSON при публикации меньше 8 МиБ |
| `data/rm-uor-dit-measurements.json` в той же ветке | Опубликованные измерения ДИТ. Файл обновляется тем же коммитом, что и основная версия. Объём меньше 8 МиБ |
| `data/rm-uor-dit-history.json` в той же ветке | Датированные наблюдения опубликованных правок. Формат `{schemaVersion: 1, events}`, объём меньше 8 МиБ |

### Основное состояние

| Ключ | Форма и назначение |
| --- | --- |
| `profile` | `name, remote, branch, refreshMinutes, theme, gitExecutable, gitAuth`. Чистые значения ветки `main`, интервала `30`, темы `indigo` и входа `system` |
| `catalogSourceId, catalog` | Активный SHA-256 и список целей `id, title, description, scope, method, target, links, curators, assignments, category, metric, status, scopeType, summary, actions, outOfScopeReason` |
| `goalEdits` | По `goalId`. Накладки названия, целевого значения, описания, методики и кураторов |
| `directory` | `id, name, type`, возможные `leaderId, aliases, edited`. Идентификатор ДИТ — `dit` |
| `sources` | `id, name, size, type, uploadedAt, sheets`. В рабочем пространстве может быть несколько версий карты и книги |
| `statusDates` | По `sourceId`. `asOf`, доступные `periods` и `revision` |
| `statusLinks` | По периоду и нормализованному ключу КР. `goalId`, возможный `scopeId`, `revision`. Связь с `null` означает осознанный пропуск |
| `drafts` | По `goalId`, внутри по `scopeId + period`. Результат с `base` и `target` для проверки конфликта при публикации |
| `ditDrafts` | Строки `goalId, period, status, revision, base, target, measurement?`. База соответствует виденному общему результату, назначение — репозиторию и ветке на момент записи |
| `ditTimeline, ditExcluded` | Локальные наблюдения и исключения применимости пары `goalId, period`. Настройка применимости действует на этой установке |
| `riskActions, qualityReports` | Локальные поручения и рассчитанные отчёты пилота |
| `automations, runs` | По `goalId`. Рецепт XLSX и последние строки расчёта с копией использованного рецепта |
| `visualization` | `revision, cards`. `cards: null` в проекции означает стандартные графики, пустой массив означает сохранённую пустую компоновку |
| `shared` | `revision, version, goals, ditStatuses, history, checkedAt, error`. Последний успешно принятый снимок и диагностика проверки |

При чтении старого состояния сервер пытается восстановить каталог из сохранившегося оригинала HTML и переводит прежние локальные статусы ДИТ в современную форму. Если каталога и исправного оригинала нет, каталог нужно импортировать заново. Правки карточек и оригиналы хранятся отдельно от активной карты.

### Общий Git-файл и копия

`data/rm-uor.json` содержит `version`, `goals: [{id, title, results}]`, `history: [{version, author, publishedAt, goalIds}]` и необязательный `ditStatuses: [{goalId, period, status, revision}]`. Обычный результат содержит `scopeId, period, value, status, plan, comment, risk, asOf, author, savedAt, mode`. Для ДИТ допустимы «Выполнено», «Под риском», «В плане», «Не выполнено», «Нет методики» и пустая строка. Пустая запись с ревизией переносит отмену явного статуса на другие установки. Коммит с новой версией увеличивает `version` на 1. Любые общие записи видны только при наличии соответствующей цели в карте установки.

Отдельный Git-файл измерений содержит `{schemaVersion: 1, measurements: [{goalId, period, measurement}]}`. Чтение объединяет два файла из одного коммита. Измерение обязано ссылаться на существующую строку ДИТ с теми же ключами. Сброшенное измерение удаляется из массива. Старый клиент обновляет только `data/rm-uor.json` и сохраняет файл измерений в дереве своего коммита. Чтение неподдерживаемой структуры, дублированного ключа или несовпадающего идентификатора сохраняет последнюю принятую общую версию.

`GET /api/backup` отдаёт `{format: "rm-uor-workspace-v1", exportedAt, workspace, originals: [{id, base64}]}`. Импорт через предпросмотр проверяет SHA-256 оригиналов и версию локального состояния. Браузерное состояние и Git-кеш лежат отдельно. Для переноса полного состояния остановите сервер и скопируйте весь каталог данных с сохранением прав и защитой личной сессии. Для повторного чтения общего результата достаточно подключения к той же ветке. [Восстановление](restore.md)

## Разбор и происхождение

**Карта.** `imports.mjs` извлекает единственный `<script id="portal-data" type="application/json">`. Обязательны массив `goals` и объект `leaders`. Идентификаторы целей уникальны, назначения указывают на известную цель. Команды, продукты и агенты в справочнике получают производные ID по типу, лидеру и имени. При замене карты каталог перестраивается, оригиналы сохраняются. Каталожные категории включают процесс, данные, архитектуру и безопасность. Карта также показывает мониторинг, снятые и внепериметровые цели.

**Книга.** `openWorkbook` читает ZIP и поддерживаемые части OOXML, листы и их видимость, строки, общие строки, диапазон фильтра и объединения. Используются сохранённые значения ячеек и кеши формул. Общий размер входа парсера до 32 МиБ, отдельного XML до 16 МиБ, распакованных частей до 128 МиБ, лимиты книги и сетки по 500 000 ячеек. Предпросмотр сервера возвращает до 100 строк, внутренний предел запроса парсера 200 строк и 256 столбцов. Импорт через HTTP ограничен 20 МиБ.

**Реестр статусов.** `status-register.mjs` ищет один подходящий видимый лист с автофильтром B:W, двумя строками заголовков и кварталом `Q1–Q4 YYYY` того же года, что и `Yyy`. B:D содержат контекст. E:I — КР, план, факт, прогресс и артефакт квартала, J:N — годовые поля. O:R — куратор, исполнитель и комментарии, S:V — прогнозы и легенды, W — наличие артефакта. Объединённые ячейки B:D восстанавливают контекст. Каждая непустая ячейка КР создаёт отдельную запись периода с ID `<номер строки>:<период>`. Строка хранит происхождение через лист и источник реестра, значения `plan, fact, progress, forecast, status` и видимые данные сверки. Для артефактов выделяются HTTPS-ссылки без учётных данных в URL.

**Сопоставление.** Явный код или точное правило из `status-goal-aliases.mjs` предлагает связь с активной картой. Несколько вариантов кода блокируют однозначное предложение. Для назначенного лидера требуется единственное совпадение ФИО или алиаса со справочником. Итог ДИТ распознаётся по нормализованному имени ДИТ или именованной итоговой строке. Ручная связь переносится между срезами по ключу записи и периоду. Повтор ключа делает строки неоднозначными. Состояния связи `confirmed, suggested, pending, unlinked, ambiguous` отображаются при сверке.

**Сравнение.** Дата задаётся вручную. При автоотборе используется последняя датированная книга, совпадение последних дат требует явного выбора. Без дат перебираются XLSX от новых к старым. Недельное сравнение требует общий период и более позднюю дату текущего среза. `status-snapshots.mjs` различает новые, сохраняющиеся и закрытые риски, пропавшие записи, неизвестный предыдущий или текущий прогноз, изменения, неоднозначные строки и отсутствие идентичности. Без предыдущего среза доступны текущие числа и список рисков.

## Проекции и вычисления

Для каждой цели, уровня и периода используются подтверждённые строки. При их отсутствии подходит одно предварительное совпадение. Несколько предварительных кандидатов оставляют статус пустым. Нормализация приводит формулировки Excel к пяти статусам. Среди нескольких подтверждённых строк риск имеет приоритет. «Выполнено» требует выполнения всех строк. Далее идёт «Не выполнено», затем «В плане». Если остаются только известные статусы без методики, показывается «Нет методики». Нераспознанный или пустой итог отображается как «Нет статуса».

Локальные и опубликованные обычные результаты участников доступны в карточках и в сценарии публикации. Реестр и счётчики лидеров опираются на применимые строки Excel. Ручной статус ДИТ — отдельное переопределение в управленческой проекции.

| Проекция | Правило |
| --- | --- |
| Цели кластера | Активное назначение из карты на лидера за период. Исключаются `monitor, removed, outOfScope` и назначения `active: false`. Похожие Excel-строки других подразделений остаются в сверке |
| Цели ДИТ | Одна активная цель карты за период. Явный ручной статус выше отдельного итога из Excel. При отсутствии данных показывается «Нет статуса». Риск кластера остаётся в кластере |
| Факт и план ДИТ | Если записано отдельное измерение ДИТ, используются его факт, план и единица. Иначе факт из единственной итоговой строки ДИТ. План из этой строки, затем из согласованного плана лидеров, доступного в проекции, затем из цели или метрики карты. Несколько итоговых строк оставляют факт пустым. Сопоставимый диапазон фактов лидеров показывается только в детализации |
| Фильтры и визуализация | Карта, реестр и графики используют общую проекцию в `goal-status.js`. В общем графике охвата назначения показаны по лидерам. Клик риска ДИТ или кластера сохраняет период и открывает соответствующий разрез реестра |
| Табличная автоматизация | Один рецепт на цель. Принимает сохранённые ячейки столбцов участника и значения и границы строк. Участник сопоставляется по справочнику. Дубли и неизвестные участники останавливают расчёт. `fraction` умножает значение на 100. Принятие переносит данные в черновики, сохраняя ранее внесённые статус, план, комментарий и риск |
| Отчёт куратора | Понедельник в UTC, для диапазона берётся неделя его конца. Даты распознаются только в заголовках. Пустая неделя остаётся пустой. В сводке для каждой категории до трёх уникальных пунктов с куратором, сначала первые позиции карточек, затем следующие |

Перед публикацией проверяются подключение, ревизия общей ветки, базы изменённых записей и токен предпросмотра. Git-переход выполняется относительно ожидаемого коммита. При конфликте черновики остаются для сверки. При ошибке чтения сохраняется последняя пригодная общая версия. Автопроверка запускается при старте и затем проверяет интервал каждые 10 секунд в системном режиме.

## Измерение ДИТ и выгрузка среза

Дата факта относится к измерению. Период относится к цели. Автор берётся из локального профиля. В приложении нет отдельной роли утверждения, автор сохраняет проверенное им основание и публикует его через предпросмотр. Введённый или рассчитанный факт сам по себе не меняет статус. Сброс числового факта оставляет статус и возвращает прежний приоритет итоговой строки Excel.

| Метод | Вход и результат |
| --- | --- |
| `manual-v1` | Числовой факт, необязательный план, единица, дата, текстовое основание. Допустимы явно введённые ноль и отрицательное число |
| `xlsx-cell-v1` | SHA-256 загруженной книги, лист, ячейка факта, необязательная ячейка плана либо введённый план и единица. Для ячеек можно явно выбрать преобразование доли в проценты |
| `xlsx-ratio-v1` | Избранные ячейки числителя и знаменателя. Формула `числитель / знаменатель × 100`, округление до шести десятичных знаков. Операнды целые. Знаменатель больше нуля, числитель от нуля до знаменателя. План указывается в процентах либо берётся из ячейки с выбранным масштабом |

Расчёт проверяет SHA-256 загруженной книги. XLSX читается как набор сохранённых значений. Текст, пустая ячейка и формула без сохранённого результата приводят к ошибке с адресом. Сохранённое измерение не заменяется при отказе. Выбор нового файла или даты создаёт другой идентификатор. Если прежний файл отсутствует на установке, для пересчёта нужно явно выбрать доступный XLSX.

Выгрузка содержит `{schemaVersion: 1, goalId, period, measurement}`. Поля `measurement` — `id, method, asOf, unit, plan, fact, origin, author, recordedAt`. Для ручного метода `origin` содержит `reference`. Для XLSX — `sourceId, name, sheet, scale, planCell` и `factCell` либо `numerator, denominator`. Каждая указанная ячейка хранит адрес в верхнем регистре и исходное число. План без выбранной ячейки может быть `null`. SHA-256 ID считается из версионного содержания, включая ключ цели, период, дату, источник, операнды, план и факт. Имя файла, автор и время записи не влияют на ID. При повторном успешном расчёте с тем же ID сохраняется прежняя запись.

Экран «Срезы ДИТ» показывает текущее измерение и отдельно историю по точным датам. Событие `goalId, period, revision, status, date, recordedAt, measurement?` фиксируется при сохранении. При создании измерения используется дата его факта, при отдельной правке статуса или сбросе — календарная дата записи UTC. Публикация сохраняет дату сохранённого наблюдения. Если на дату было несколько правок цели, показывается последняя по времени записи. Сравнение вычисляет дельту только в одинаковых единицах, проценты выражаются в процентных пунктах. Пропуск остаётся пустым.

Технический журнал начинается с этой версии. Для прежних записей восстанавливаются только текущие измерения с известной датой факта. Для старых статусов без даты история не достраивается. Предыдущие события общей истории защищены от пропуска или изменения при чтении Git. Экспорт текущего измерения доступен и из карточки цели. [Контракт многодатного обмена](navigator-integration.md)
