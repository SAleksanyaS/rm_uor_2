## Автоматизированные проверки

Запуск из корня `npm test` или `node --test`. Для Git-сценариев нужен рабочий Git и запись во временную папку. Сценарии используют локальные тестовые репозитории. Точные предусловия дополнительных прогонов указаны после таблицы.

| Файл | Что проверяется |
| --- | --- |
| `test/workspace.test.mjs` | Жизненный цикл состояния, импорт, локальные правки, HTTP, бэкап, конкурентный предпросмотр, откат общей версии и черновики ДИТ |
| `test/dit-timeline.test.mjs` | Даты сохранения и измерения, пропуски, ноль и сравнимость единиц |
| `test/risk-actions.test.mjs` | Привязка, конфликт ревизии и подготовка запроса для адаптера |
| `test/quality-pilot.test.mjs` | Две книги, смена даты и факта, валидация порога и пропуска |
| `test/workspace-restore.test.mjs` | Совместимость, проверка байтов и привязка токена к превью |
| `test/meeting-report.test.mjs`, `test/meeting-view.test.mjs` | Полный охват, фильтр, редактирование и показ слайдов |

| `test/status-register.test.mjs` | Два периода, поля и строки книги, заголовки, дата и повторное применение связей |
| `test/status-goal-aliases.test.mjs` | Точный контекст формулировок, форматы мер, конфликтующие пороги |
| `test/status-snapshots.test.mjs` | Идентичность КР, порядок дат, изменения рисков, отсутствие строк и неизвестные статусы |

| `test/status-view.test.mjs` | Отображение плана и факта, детализация нескольких КР, выбор ДИТ и лидера |

| `test/browser-connector.test.mjs` | Профили и сеть, TLS-границы, чтение, скачивание, отмена и запись кликов |
| `test/browser-workspace.test.mjs` | Хранение, ревизии, уникальность кураторов, асинхронное получение, отмена, сохранение предыдущего отчёта |
| `test/browser-scenario.test.mjs` | Версионный JSON, ограничения переносимости и отображение управления записью |
| `test/weekly-curator-parser.test.mjs` | Даты, интервалы, заголовки, пустые секции и конфликтующие блоки |
| `test/weekly-curators.test.mjs` | Архив после повторного чтения и рестарта, пустая карточка за пропущенную неделю |

`RMUOR_REAL_STATUS_XLSX` — путь к реальной книге для дополнительной проверки реестра. `RM_UOR_REAL_BROWSER_TEST=1` включает дополнительный сценарий с локальной тестовой страницей. Для него `RM_UOR_PLAYWRIGHT` задаёт путь к установленному Playwright. `RM_UOR_BROWSER` при необходимости задаёт путь к выбранному Chromium. Эти тесты могут пропускаться в обычном запуске.

Контрольный прогон от 16 ноября 2026 года включил приложенный XLSX, локальные сценарии Git и сценарий Playwright с реальным Chromium. Прошёл 101 тест. Общий и кластерный PowerPoint скачаны в Chrome и проверены отрисовкой всех слайдов. Дополнительно локальный интерфейс проверен через Chrome для карты, истории ДИТ, поручений, пилота и восстановления.

## Приёмка и ограничения доказательств

| Область | Приёмка |
| --- | --- |
| Запуск | Чистая распаковка и `npm run dev` на Windows, macOS и Linux, повторный запуск с сохранившейся правкой |
| Данные | Одна карта и книга на двух установках, контроль чисел и приоритета источника, переход до строки Excel |
| Публикация | Две установки на целевом Git, чтение, публикация и получение ручного статуса ДИТ, конфликт и повторная сверка |
| Интеграции | Реальный корпоративный браузер, вход и получение по одному отчёту выбранного типа. Проверяются адреса SSO, видимый блок, выгрузка и структура книги |
| Интерфейс | Клавиатура, узкий экран, тёмная тема, переходы к риску и пустой результат |
| Эксплуатация | Перезапуск, резервная копия, сохранение результатов при отказе Git и браузера. Восстановление полного каталога проверяется отдельным прогоном |

Список связывает документацию с проверками. Запуски тестов с локальными данными подтверждают соответствующие сценарии этой копии. Проверки внутренних сайтов, рабочих учётных записей, восстановления и всех целевых ОС требуют своей среды.

## Диагностика установки

| Симптом | Что сверить |
| --- | --- |
| Порт занят или открывается другой экземпляр | Адрес, напечатанный в консоли. При необходимости задать `RM_UOR_PORT` и перезапустить |
| Чистый запуск без карты | Каталог данных и имя переменной `RM_UOR_DATA_DIR`. Пользовательский путь запускается пустым, карту и книгу туда загружают через «Источники» |
| Факт пустой или число целей изменилось | Активную карту, книгу и период. Для кластера — назначение и связь в «Сверке КР». Для общего факта — отдельную итоговую строку ДИТ |
| Два среза с одной датой | Выбрать книгу явно. Для сравнения указать разные даты и общий период |
| Git не найден | Установку Git и возможность запуска из `PATH` или проверенный полный путь в профиле |
| Git не принимает отправку | Адрес, ветку, права записи и последнюю проверку. При конфликте обновить общий срез, сверить правки и заново открыть предпросмотр |
| Отчёт пропущен или не загружается | [Диагностику браузерных подключений](../browser-connectors.md#хранение-и-диагностика) |

## Поддержание SDD

Для изменения поведения сначала обновляется правило в [мастер-спецификации](../MASTER_SPEC.md) или фиксируется новая задача в плане. После реализации сверяются затронутые экран, контракт, данные, ограничения и существующие тесты. Матрица пополняется при добавлении модуля или теста. Приёмка целевой среды отмечается по реально выполненным сценариям.
